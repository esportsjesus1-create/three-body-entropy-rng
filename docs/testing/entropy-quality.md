# Entropy Quality Testing Documentation

This document provides comprehensive documentation for the entropy quality assurance testing system used to validate the randomness of the three-body physics entropy generator.

## Introduction

The Three-Body Entropy RNG system generates random values by simulating chaotic three-body gravitational dynamics. To ensure these values are suitable for cryptographic and gaming applications, we employ a rigorous statistical testing framework based on the NIST SP 800-22 randomness test suite.

## Why Entropy Quality Matters

For provably fair gaming applications, the quality of entropy directly impacts fairness and security. Poor entropy can lead to predictable outcomes that could be exploited by malicious actors, undermining the integrity of the gaming system. Our testing ensures that the entropy generated by the three-body simulation exhibits the statistical properties expected of truly random data.

## NIST SP 800-22 Overview

The National Institute of Standards and Technology (NIST) Special Publication 800-22 defines a statistical test suite for evaluating random and pseudorandom number generators. Our implementation includes the following tests from this suite.

### Frequency (Monobit) Test

The frequency test is the most basic test of randomness. It determines whether the number of ones and zeros in a binary sequence are approximately equal, as would be expected for a truly random sequence.

**How it works**: The test counts the number of ones in the sequence and calculates the proportion. For a random sequence, this proportion should be close to 0.5. The test statistic measures the deviation from this expected value.

**Mathematical formulation**: Given a sequence of n bits, let S_n be the sum where each 0 is counted as -1 and each 1 is counted as +1. The test statistic is S_obs = |S_n| / sqrt(n). The p-value is calculated using the complementary error function: p-value = erfc(S_obs / sqrt(2)).

**Interpretation**: A p-value greater than 0.01 indicates that the sequence passes the test with 99% confidence. A low p-value suggests the sequence has a bias toward ones or zeros.

### Runs Test

The runs test examines the total number of runs in the sequence, where a run is an uninterrupted sequence of identical bits. This test determines whether the oscillation between zeros and ones is too fast or too slow for a random sequence.

**How it works**: The test first verifies that the proportion of ones is close enough to 0.5 (pre-test). Then it counts the number of runs and compares this to the expected number for a random sequence.

**Mathematical formulation**: Let π be the proportion of ones. The expected number of runs is 2nπ(1-π). The test statistic measures the deviation of the observed runs from this expected value.

**Interpretation**: Too few runs suggests the sequence has long stretches of identical bits. Too many runs suggests the sequence alternates too frequently. Both conditions indicate non-randomness.

### Chi-Square Test for Uniformity

The chi-square test verifies that values are uniformly distributed across the possible range. For entropy values, this ensures no clustering in certain ranges.

**How it works**: The test divides the range of possible values into buckets and counts how many samples fall into each bucket. For a uniform distribution, each bucket should have approximately the same count.

**Mathematical formulation**: χ² = Σ (O_i - E_i)² / E_i, where O_i is the observed count in bucket i and E_i is the expected count. The p-value is calculated from the chi-square distribution with k-1 degrees of freedom.

**Interpretation**: A high chi-square value (low p-value) indicates the distribution is not uniform. This could mean the entropy generator favors certain values over others.

### Shannon Entropy Estimation

Shannon entropy measures the information content of the data. Maximum entropy indicates maximum randomness.

**How it works**: The test calculates the probability distribution of symbols in the data and computes the Shannon entropy formula.

**Mathematical formulation**: H = -Σ p(x) * log₂(p(x)), where p(x) is the probability of symbol x. The maximum entropy for k symbols is log₂(k).

**Interpretation**: The entropy ratio (actual/maximum) should be at least 95% for high-quality randomness. Lower values indicate patterns or biases in the data.

## Expected P-Values

All statistical tests produce a p-value that indicates the probability of observing the test result (or more extreme) if the sequence were truly random.

### Significance Level

We use a significance level of α = 0.01, meaning we require 99% confidence that the entropy is random. A test passes if its p-value exceeds 0.01.

### P-Value Interpretation Guide

| P-Value Range | Interpretation | Action |
|---------------|----------------|--------|
| > 0.10 | Strong evidence of randomness | Pass |
| 0.01 - 0.10 | Acceptable randomness | Pass |
| 0.001 - 0.01 | Borderline, may need investigation | Fail |
| < 0.001 | Strong evidence of non-randomness | Fail |

### Expected Results for True Random Data

For truly random data, p-values should be uniformly distributed between 0 and 1. When running multiple tests, approximately 1% of tests may fail by chance at the 0.01 significance level. This is expected behavior and does not indicate a problem with the entropy generator.

## How to Interpret Results

### Successful Test Run

A successful test run will show all tests passing with p-values above 0.01. Example output:

```
NIST Test Suite Results:
Overall passed: true
Overall p-value: 0.234567

Frequency (Monobit) Test:
  Passed: true
  P-value: 0.456789
  Details: S_n = 42, S_obs = 0.042105, n = 1000000

Runs Test:
  Passed: true
  P-value: 0.345678
  Details: Runs = 500234, Expected = 500000.00, pi = 0.500021
```

### Failed Test Investigation

If a test fails, follow these steps:

1. **Check the specific test that failed**: Different failures indicate different problems.
2. **Review the p-value**: A p-value just below 0.01 may be a statistical fluke. Re-run with more samples.
3. **Check the test statistic**: This provides insight into the nature of the failure.
4. **Review recent changes**: If the physics simulation was modified, the change may have affected entropy quality.
5. **Increase sample size**: Some failures are due to insufficient data. Try running with 10000+ samples.

### Common Failure Patterns

**Frequency test failure**: The entropy has a bias toward ones or zeros. Check the physics simulation for asymmetries.

**Runs test failure**: The entropy has too much or too little oscillation. This could indicate periodic behavior in the simulation.

**Chi-square test failure**: Values are clustering in certain ranges. Check for truncation or rounding issues in the entropy extraction.

**Low entropy**: The data has patterns or redundancy. Check for deterministic behavior in the simulation.

## Test Configuration

### Sample Sizes

The number of samples affects the statistical power of the tests:

| Sample Size | Use Case | Approximate Runtime |
|-------------|----------|---------------------|
| 100 | Quick sanity check | < 1 minute |
| 1000 | Standard CI testing | 3-5 minutes |
| 10000 | Extended validation | 30-60 minutes |
| 100000 | Comprehensive audit | Several hours |

### Recommended Configurations

**Development**: Run with 100-500 samples for quick feedback during development.

**CI/CD**: Run with 1000 samples on every pull request. This provides good statistical power while keeping build times reasonable.

**Release validation**: Run with 10000+ samples before major releases to ensure high confidence in entropy quality.

## CI/CD Integration

The entropy quality tests are integrated into the CI/CD pipeline via GitHub Actions.

### Workflow Configuration

The workflow file `.github/workflows/entropy-quality.yml` defines two jobs:

1. **entropy-quality-tests**: Runs on all PRs with 1000 samples
2. **entropy-quality-extended**: Runs on main branch pushes with 10000 samples

### Handling CI Failures

If entropy quality tests fail in CI:

1. Check the GitHub Actions log for detailed test output
2. Identify which specific test failed
3. Review the p-value and test statistic
4. If borderline (p-value close to 0.01), re-run the workflow
5. If consistently failing, investigate the entropy generation code

## Extending the Test Suite

### Adding New Tests

To add a new statistical test:

1. Implement the test function in `tests/entropy-quality/utils/nist-tests.ts`
2. Export the function and add it to the `runNISTTests` function
3. Add a corresponding test case in `tests/entropy-quality/entropy-quality.test.ts`
4. Update this documentation

### Test Function Template

```typescript
export function newTest(binaryString: string): NISTTestResult {
  // Validate input
  if (binaryString.length < MINIMUM_LENGTH) {
    return {
      testName: 'New Test',
      passed: false,
      pValue: 0,
      statistic: 0,
      details: 'Insufficient data'
    };
  }

  // Calculate test statistic
  const statistic = calculateStatistic(binaryString);
  
  // Calculate p-value
  const pValue = calculatePValue(statistic);

  return {
    testName: 'New Test',
    passed: pValue >= 0.01,
    pValue,
    statistic,
    details: `Statistic = ${statistic.toFixed(6)}`
  };
}
```

## Appendix: Mathematical Details

### Complementary Error Function (erfc)

The complementary error function is defined as:

erfc(x) = 1 - erf(x) = (2/√π) ∫_x^∞ e^(-t²) dt

We use the Horner form approximation for computational efficiency.

### Incomplete Gamma Function

The incomplete gamma function P(a, x) is used for chi-square p-value calculation:

P(a, x) = (1/Γ(a)) ∫_0^x t^(a-1) e^(-t) dt

We use series expansion for small x and continued fraction for large x.

### Chi-Square Distribution

The chi-square distribution with k degrees of freedom has PDF:

f(x; k) = (x^(k/2-1) e^(-x/2)) / (2^(k/2) Γ(k/2))

The CDF is the regularized incomplete gamma function: F(x; k) = P(k/2, x/2)
